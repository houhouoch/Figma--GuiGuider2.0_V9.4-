# Figma 到 GUI Guider 必须采用候选工程晋升门禁

## 结论

Figma 全量同步结果不能直接覆盖正式 `.guiguider`。应先生成独立候选，完成自动验证、GUI Guider 人工审核和显式授权，再晋升正式工程。

## 最小门禁

1. 记录正式工程 SHA-256 并建立可恢复备份。
2. 生成独立候选，不修改正式工程。
3. 两次生成语义结果一致。
4. 结构、对象身份、资源和关键视觉区域无阻断。
5. 对控件类型变化、滚动页、弹层和高层级变化页面做人工审核。
6. 用户明确授权晋升。
7. 只替换获批 UI 树，保留正式工程非 UI 配置。
8. GUI Guider 打开、保存、关闭后比较 JSON。
9. 重新生成 C 并完整构建。

## 已验证证据

UDP3900 GUI Guider 2.0 项目中：

- 候选两次生成 SHA-256 相同；
- 结构阻断项为 0；
- V8 契约回归差异为 0；
- 正式工程保存后只有 `lastModified` 改变；
- UI 树和资源引用保持不变。

## 防错规则

- 自动相似度不能代替人工审核。
- GUI Guider 能打开不能代替代码生成和编译。
- 没有显式授权时必须停在候选阶段。
